# АвтоАналоги

Веб-каталог запчастей и аналогов для легковых автомобилей: **Django 5.2 + MySQL 8.4**, русскоязычный адаптивный интерфейс. Доступ только после входа. Учётные записи создаёт администратор; публичной регистрации нет.

## Быстрый запуск на Windows без Docker

1. Установите Python 3.12 x64 и MySQL Server 8.4, если они ещё не установлены.
2. Скачайте проект кнопкой **Code → Download ZIP** на GitHub и распакуйте весь архив в новую папку.
3. Запустите **install-windows-native.cmd**. При запросе введите пароль MySQL `root`.
4. После завершения установки запустите **start-windows-native.cmd** — сайт откроется в браузере.

Логин сайта — `admin`, начальный пароль находится в локальном `.env`, после `DJANGO_SUPERUSER_PASSWORD=`. Этот файл генерируется на вашем компьютере и не включён в репозиторий. Готовые зависимости находятся в `vendor/wheels`: для их установки не нужен интернет. Подробности — в [WINDOWS-NATIVE.md](WINDOWS-NATIVE.md).

Для запуска на Windows смотрите [WINDOWS.md](WINDOWS.md). После установки Docker Desktop достаточно распаковать проект и запустить `start-windows.cmd`.

Для **Windows без Docker** используйте [WINDOWS-NATIVE.md](WINDOWS-NATIVE.md): установите Python 3.12 x64 и MySQL 8.4, затем запустите `install-windows-native.cmd` и `start-windows-native.cmd`. Этот вариант использует Waitress и отдельный `requirements-windows.txt`.

## Возможности

- Поиск по артикулу, производителю и названию. Пробелы, дефисы и регистр в артикуле не влияют на поиск.
- Фильтры по производителю, категории и автомобилю; постраничный вывод.
- Карточка детали с описанием, источником и применяемостью.
- Ручные связи аналогов с источником, условиями замены и отметкой проверки.
- Импорт запчастей, ручных связей и исходного формата `example.csv`.
- Административная панель для пользователей, производителей, автомобилей и каталога.
- Хеширование паролей, CSRF-защита, экранирование HTML, блокировка входа на 15 минут после 5 неудачных попыток для пары «имя пользователя + IP».

## Запуск через Docker

Нужны Docker Engine, Docker Compose v2 и Python 3 для генерации локального `.env`.

```sh
python scripts/init_env.py
docker compose up -d --build --wait
docker compose exec web python manage.py bootstrap_admin
docker compose exec web python manage.py import_catalog references data/example.csv
```

Приложение слушает порт **8000 только на локальном интерфейсе сервера**. Веб-сервис использует Gunicorn, MySQL не публикуется наружу. `.env` содержит случайные локальные секреты и не попадает в Git или Docker-образ. Имя начального администратора — `admin`; сгенерированный пароль хранится в локальном `.env`, поле `DJANGO_SUPERUSER_PASSWORD`. Команда `bootstrap_admin` не меняет существующую учётную запись. После первого входа смените пароль через меню пользователя.

Можно вместо начальной учётной записи создать свою интерактивно:

```sh
docker compose exec web python manage.py createsuperuser
```

`data/example.csv` — предоставленный пользователем пример каталога, 1000 строк. Импорт не выдумывает названия деталей и применяемость: отсутствующие названия помечаются «Название не указано». Эти сведения можно заполнить позже.

## Права пользователей

В `/admin/` администратор создаёт пользователей и задаёт пароли.

- Обычный активный пользователь: поиск и просмотр каталога.
- Пользователь с флагом **Статус персонала** (`is_staff`): добавление и редактирование деталей, создание/удаление ручных связей, CSV-импорт в основном интерфейсе.
- Для редактирования моделей в административной панели сотруднику нужно дополнительно выдать соответствующие Django-разрешения. Управление пользователями рекомендуется оставить суперпользователю.

Удаление запчастей и управление исходными связями доступны через панель администратора с соответствующими разрешениями. Выход выполняется POST-запросом. Забытый пароль администратор меняет в панели; почтового восстановления в этой версии нет. Снять блокировку можно командой `docker compose exec web python manage.py axes_reset_username USERNAME`.

## Импорт CSV

Импорт доступен сотрудникам в интерфейсе и через `manage.py import_catalog`. UTF-8 или UTF-8 BOM, до 2 МБ и 5000 строк. При ошибке **весь импорт отменяется**. Повторный импорт обновляет существующие записи. Артикулы сохраняются строками, в том числе с ведущими нулями.

### Исходный каталог связей

```text
source_oem;source_brand;relation_code;relation_name;direction;related_oem;related_brand;weight;rate;last_seen_at
```

Разделитель — `;`. Две детали создаются при необходимости. Сохраняются исходный и связанный артикулы, бренды, код и название отношения, `forward`/`reverse`, вес, рейтинг, дата и имя файла. Числа с десятичной запятой поддерживаются. `\N` и пустые значения веса, рейтинга и даты означают NULL. Даты без часового пояса интерпретируются как **Europe/Moscow** и хранятся в UTC.

Исходные записи хранятся отдельно от ручных симметричных связей. Направление показывается как в исходном файле; приложение не интерпретирует его как подтверждение двусторонней взаимозаменяемости. Рейтинг не превращается в отметку проверки. Транзитивные аналоги не вычисляются: связь A–B и B–C не создаёт A–C. Применяемость одного артикула не переносится на другой.

### Запчасти

```text
manufacturer,article,name,category,description,source
```

Разделитель — `,`. Обязательны первые три колонки. Уникальный ключ — производитель и нормализованный артикул. Необязательные колонки обновляются только при наличии в файле; применяемость CSV не меняет.

### Ручные связи аналогов

```text
manufacturer,article,analog_manufacturer,analog_article,source,note,verified
```

Разделитель — `,`. Обязательны первые пять колонок. Обе детали должны существовать. `verified`: `1`/`true` либо `0`/`false`; по умолчанию связь не проверена. Пара уникальна независимо от порядка деталей.

## Структура базы

Миграции Django создают таблицы MySQL с кодировкой utf8mb4, внешними ключами и ограничениями:

| Модель | Данные |
| --- | --- |
| Manufacturer | Производитель запчасти |
| Part | Артикул, нормализованный ключ, название, категория, описание, источник |
| Vehicle | Марка, модель/поколение, двигатель, годы выпуска |
| Part.vehicles | Связь многие-ко-многим для применяемости |
| Analogue | Уникальная упорядоченная пара деталей, источник, примечание, проверка |
| CrossReference | Исходная направленная запись каталога и её метаданные |
| Django auth/session/axes | Пользователи, права, сессии и ограничение попыток входа |

## Проверки

```sh
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
sh scripts/test.sh
```

Тесты работают на настоящем MySQL в отдельной временной базе `test_autoparts`; проверяют вход/выход, блокировку, права, CSRF, поиск, ограничения уникальности, HTML-экранирование, импорт и откат ошибок. Для создания тестовой базы только тестовая команда использует root; веб-сервис работает от ограниченного пользователя БД.

## Разработка

После изменения исходников пересоберите веб-образ: `docker compose up -d --build web`. После изменения моделей создайте и сохраните миграции. Для интерактивного запуска Django используйте отдельный Compose-процесс с публикацией порта после остановки основного веб-сервиса:

```sh
docker compose stop web
docker compose run --rm --service-ports web python manage.py runserver 0.0.0.0:8000
```

Облачная задача уже изолирована: работайте в текущем checkout, создавать отдельный Git worktree не требуется.

### Сборка в облачной среде с прокси

Полная повторяемая настройка в этой облачной среде:

```sh
sh scripts/setup.sh
```

Скрипт сохраняет существующий `.env` и учётную запись администратора, собирает образ, запускает сервисы и загружает пример только если таблица исходных связей пуста. Повторный запуск не перезаписывает заполненный каталог.

Если Docker не разрешает имя прокси или не знает его CA, используйте:

```sh
python scripts/cloud_build.py
DOCKER_CONFIG=/tmp/autoparts-docker docker compose up -d --no-build --wait
```

Скрипт использует текущий HTTP(S)-прокси, добавляет его DNS-адрес на время сборки и передаёт публичный CA-bundle как временный BuildKit secret. Проверка TLS и подписей пакетов остаётся включённой. Настройки и сертификаты прокси не встраиваются в образ. Если в среде нет прокси, используйте стандартную сборку Compose.

## Данные и размещение

MySQL хранит данные в именованном Docker volume `mysql_data`; обычный перезапуск их сохраняет. Не выполняйте `docker compose down -v`, если данные нужны. Перед обновлениями делайте резервную копию и проверяйте восстановление:

```sh
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump -u "$MYSQL_USER" --no-tablespaces --single-transaction "$MYSQL_DATABASE"' > backup.sql
# Восстановление в подготовленную базу (заменяет данные при наличии SQL DROP/CREATE):
# docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u "$MYSQL_USER" "$MYSQL_DATABASE"' < backup.sql
```

Для публичного размещения настройте домен и HTTPS через обратный прокси на том же сервере, задайте `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` и `DJANGO_HTTPS=true`, оставьте `DJANGO_DEBUG=false`. При TLS-терминации отдельно настройте доверие к заголовкам своего прокси; по умолчанию приложение не доверяет произвольному `X-Forwarded-Proto`. Публичный домен и развёртывание на внешнем сервере в этот проект не входят. `.env`, SQL-копии и исходный каталог должны храниться с ограниченным доступом.
